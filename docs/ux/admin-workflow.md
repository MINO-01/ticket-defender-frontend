# 관리자 업무 흐름과 화면 구성

기준 브랜치: `feat/capstone-demo-ux-20261108` (main 0504361에서 분기)

관리자가 암표 의심 제보를 받고, 근거를 확인해 조사 사건으로 만들고, 독립 승인과 보고서 발급까지 진행하는 흐름을 화면 기준으로 정리합니다. 분석 결과와 상태는 조사 지원 정보이며 부정 거래 판정이 아닙니다.

## 업무 흐름

```
팬 제보 접수 → 이미지 정보 추출 → (검증 회차 연결) → 예매 기록 비교 → 조사 사건 → 승인 검토 → 보고서 발급
예매 관계 분석(연결된 예매 그룹) ───────────────────────────────↗
```

예매 관계 분석은 팬 제보와 별개로 조사 사건에 합류하는 진입 경로입니다.

## 화면 용어

API enum과 DB 필드명은 바꾸지 않고 화면 문구만 바꿉니다. 정의는 `src/app/terms.ts`에 있습니다.

| 내부 이름 | 화면 이름 |
|---|---|
| Track 1 | 예매 관계 분석 |
| Track 2 | 팬 제보 조사 |
| Cluster | 연결된 예매 그룹 |
| Case | 조사 사건 |
| Listing Analysis | 이미지 정보 추출 |
| Candidate Match | 예매 기록 비교 |
| MATCH_CANDIDATE | 일치 예매 후보 |
| EvidenceSnapshot | 조사 근거 묶음 |
| ReportVersion | 조사 보고서 초안 |
| ApprovalRequest | 보고서 승인 요청 |

접수 상태 `RECEIVED`는 "접수 완료"(증거 저장 확인)로 표시합니다. 담당자가 아직 보지 않은 신규 제보라는 뜻이 아니며, 이미지 정보 추출 완료를 뜻하지도 않습니다. `STORAGE_FAILED`(접수 실패)와 `ANALYSIS_FAILED`(분석 실패 기록)는 다른 상태로 표시합니다.

| 운영 | 설정 | `/app/settings` | 일부 (접근 공연, 인증 점검, 역할과 설정은 계약 대기) |

"일부 지원" 메뉴에는 사이드바에 표시가 붙고, 화면 안에서 "Backend 계약 대기, 완료된 기능이 아닙니다"를 표시합니다. 필요한 계약은 `docs/contracts/backend-requests.md`에 있습니다.

## 화면 공통 구성

주요 상세 화면(팬 제보, 연결된 예매 그룹, 조사 사건, 승인 요청, 공식 PDF 발급) 상단에 `WorkGuide`를 둡니다.

- **확인한 사실**: 그 화면이 받은 서버 응답에서 나온 내용만 넣습니다.
- **아직 확인되지 않은 내용**: 미검증 입력, 서버가 제공하지 않는 정보, 판정이 아니라는 안내를 넣습니다.
- **다음 작업**: 저장된 상태에 따라 가능한 다음 행동을 안내합니다. 실제 가능 여부는 서버가 요청마다 판단합니다.

UUID, revision, digest, 멤버십 ID는 `TechnicalDetails`(접힌 기술 상세)로 옮겼습니다. 값은 감사와 문의용으로 그대로 남아 있습니다.

## 안전 원칙 반영

- 접수번호는 서버의 `receiptNumber`만 사용하고, 없으면 "접수번호 미제공"과 제보 ID 앞부분을 표시합니다. 번호를 만들지 않습니다.
- 공식 PDF 발급 가능 여부는 조사 사건 상태로 추측하지 않고, 보고서 발급 화면에서 서버 적격성(`CURRENT`, `STALE`, `BLOCKED`)으로만 표시합니다. 발급 완료는 발급 기록의 서버 상태로만 표시합니다.
- 자기 승인 금지, 근거 변경 시 무효화(`INVALIDATED`), 예매 기록 비교 출처의 `APPROVAL_BASIS_BLOCKED`, 승인 없는 발급 금지, 권한 없는 다운로드 차단은 서버 정책 그대로이며, 화면은 이유를 업무 문구로 설명합니다.
- 예매 관계 분석은 저장된 예매 기록 참조만 표시하고 공유 신호나 그래프 간선을 만들지 않습니다.

## Chrome 시연 순서 (세 저장소 통합 후)

1. `/app/overview`: 공연 선택, 영역별 건수와 "다음 업무" 확인
2. 사이드바 "접수 완료된 제보": 제보 목록에서 접수번호(또는 미제공 안내), 공연, 유형, 접수일, 상태 확인
3. 제보 "조사 열기": 진행 요약과 단계 이동, 증거 미리보기, 이미지 정보 추출 실행과 이력
4. 같은 화면 "검증 회차 연결", 추출 결과별 "예매 기록 비교" 실행과 후보 선택
5. 같은 화면 "조사 사건 생성"
6. 조사 사건 상세: 진행 요약, 연결 근거, 담당자 지정, 상태 변경, 조사 근거 묶음, 보고서 초안, 승인 요청
7. 승인 요청 상세: 역할 안내, 다른 계정의 승인 담당으로 독립 검토와 결정
8. 결정 결과의 링크로 공식 PDF 발급 화면: 발급 가능 여부와 발급, 다운로드 (합성 격리 환경만)
9. 별도 경로: "예매 관계 분석"에서 연결된 예매 그룹 근거 확인 후 조사 사건 생성
10. 운영: 감사 기록에서 조사 사건 활동 기록, 분석 작업과 설정의 실제 조회 범위와 계약 대기 안내
